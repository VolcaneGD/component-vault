# Component Vault Agent CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (\`- [ ]\`) syntax for tracking.

**Goal:** Add a safe local CLI that agents can use to manage Component Vault while the Electron GUI is open.

**Architecture:** The Electron main process is the only DB writer while the GUI is open and exposes an authenticated user-scoped named-pipe broker. The CLI calls that broker or, only when no broker owns the operation lock, uses a one-command headless service runtime. One typed command registry drives handlers, JSON schemas, help, the agent guide, and the Codex skill.

**Tech Stack:** Electron, TypeScript, Node \`net\`, better-sqlite3, Vitest, Playwright, electron-builder.

## Global Constraints

- JSON is the command protocol; diagnostics go to stderr.
- Existing component mutations require an expected revision and never auto-merge.
- The pipe is local, user-scoped, capability-authenticated, and request-size-bounded.
- GUI and CLI use the same service validation, transactions, soft delete, import/export, and preview policy controls.
- The live JSON agent guide is the sole command reference.
- Preserve unrelated changes; use \`apply_patch\` for edits.
- Package verification exercises GUI-open CLI mutation and headless CLI operation.
